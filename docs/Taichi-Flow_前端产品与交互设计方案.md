# Taichi-Flow 前端产品与交互设计方案

> 文档类型：前端产品定义与完整落地规格  
> 适用对象：产品设计、UI/UX、前端开发、后端联调与验收人员  
> 设计方向：Microsoft Fluent 2，桌面端科研计算工作台  
> 代码基线：`C:\Users\Administrator\Desktop\Taichi-Flow`（2026-08-02）

## 1. 产品定义

Taichi-Flow 是面向洪水与泥石流数值模拟的本地桌面工作台。用户在项目中维护一套共享输入数据，以不同计算参数建立多个方案，将方案加入模拟队列，查看各方案的计算状态与结果，并导出指定方案的数据。

核心业务链路：

```text
项目 → 共享输入版本 → 参数方案 → 模拟队列 → 运行记录 → 结果族 → 数据导出
```

产品必须解决四个核心问题：

1. 集中管理一个计算项目的共享输入文件。
2. 在不复制输入文件的前提下维护多套计算参数。
3. 按顺序执行多套方案，并清楚展示状态与失败原因。
4. 将每次模拟结果与对应参数方案可靠绑定并导出。

## 2. 代码真源与能力边界

### 2.1 当前技术栈

- 前端：React 19、TypeScript、Vite、React Router、Zustand、Lucide React。
- 桌面端：Electron。
- 后端：FastAPI。
- 数据：全局项目目录与项目级 SQLite 状态库。
- 实时状态：WebSocket 快照；断线后使用 REST 轮询恢复。
- 视觉实现：现有自定义组件和 CSS Design Tokens，可继续演进为 Fluent 2 组件体系。

### 2.2 已存在的真实能力

| 领域 | 当前能力 |
| --- | --- |
| 项目 | 列表、新建、导入、查看、修改名称与说明 |
| 输入 | 上传、文件族分类、创建不可变输入版本、校验输入版本 |
| 方案 | 新建、修改、复制、归档、删除、保存参数补丁 |
| 队列 | 加入队列、顺序调整、取消、停止、失败重试、持久化 |
| 模拟 | 状态、进度、计算时间、步数、输出数、耗时、终端日志 |
| 结果 | 结果族索引、元数据、单文件下载、完整 ZIP 下载、删除 |
| 导出 | 按模拟记录选择结果族或文件，异步生成并下载导出包 |
| 系统 | 健康状态、CPU/GPU 使用率、参数目录 |

### 2.3 必须遵守的业务约束

- 一个项目可以有多个输入版本，但每个方案只引用一个确定的输入版本。
- 同一项目下的方案共享输入数据；方案只保存参数差异与有效参数快照。
- 已有运行历史、已完成或已归档的方案不可直接修改，应复制后编辑。
- 参数只有在参数目录中标记为 `editable` 时才允许编辑。
- `parsed_only`、`mapped_only`、`metadata_only` 等未进入生产运行链的参数只读展示。
- 不修改求解器物理公式、源项时序、干湿门槛、八方向顺序、时间步和输出语义。
- `hydrograph.txt` 表示监测输出选择，不得作为入流强迫；入流使用 `inflow.txt`。

## 3. 信息架构

### 3.1 一级页面

| 路由 | 页面 | 核心任务 |
| --- | --- | --- |
| `/projects` | 项目列表 | 新建、导入、搜索和打开项目 |
| `/projects/:projectId` | 项目概览 | 查看共享输入、方案、队列和结果摘要 |
| `/projects/:projectId/scenarios` | 方案管理 | 管理不同参数预设及其模拟状态 |
| `/projects/:projectId/scenarios/:scenarioId/calculate` | 计算工作台 | 输入、参数、运行和结果的主工作区 |
| `/projects/:projectId/queue` | 模拟队列 | 安排和监控多套方案顺序执行 |
| `/projects/:projectId/export` | 导出数据 | 选择方案、运行记录和输出数据导出 |
| `/settings` | 设置 | 主题、运行环境和系统状态 |

明确删除：

- 两方案对比。
- 诊断中心。
- “导出复现证据”概念。

### 3.2 全局导航

进入项目后，左侧导航固定提供：项目概览、方案管理、模拟队列、导出数据。计算工作台通过方案进入，不作为无上下文的一级入口。

顶部区域仅保留：当前项目切换、API/运行环境状态、CPU/GPU 简要指标、主题和设置。运行详情不应塞入全局顶栏。

## 4. 核心数据模型

```text
Project
 ├─ InputRevision 1..n
 │   └─ InputFile 1..n
 ├─ Scenario 0..n
 │   ├─ input_revision_id
 │   ├─ parameter_patch
 │   └─ effective_parameters
 ├─ QueueItem 0..n
 │   └─ SimulationRun 0..1
 └─ ExportJob 0..n
```

前端展示时必须始终明确三个对象：当前项目、当前方案、当前模拟记录。结果属于模拟记录，而不是抽象地属于项目。

## 5. 页面规格

### 5.1 项目列表

项目卡片展示：名称、路径、更新时间、共享输入版本数、方案数、队列状态。主操作为“打开”，次操作为“编辑信息”和“从最近记录移除”。

页面顶部提供：

- 新建项目：输入项目名称、本地根目录和可选说明。
- 打开本地项目：注册已有 Taichi-Flow 项目目录。
- 导入兼容算例：仍调用项目导入能力，但文案需说明不会自动改变原始文件。
- 搜索：按名称和本地路径过滤。

空状态只提供两个主入口：“新建项目”和“打开本地项目”。

### 5.2 项目概览

项目概览是任务导航页，不设计成装饰性仪表盘。按以下顺序展示：

1. 下一步行动：根据输入、方案与队列状态提供唯一主操作。
2. 共享输入：当前输入版本、文件完整度、错误与警告数量。
3. 方案状态：草稿、就绪、排队、运行、完成和失败数量。
4. 模拟队列：当前运行方案与等待数量。
5. 最近结果：最近完成的方案及结果族数量。

状态驱动的主操作优先级：配置输入 → 新建方案 → 查看当前模拟 → 查看队列 → 加入队列 → 导出数据。

### 5.3 方案管理

方案管理替代方案对比，是项目中管理不同参数预设和结果入口的核心页面。

每行或每张紧凑卡片展示：

- 方案名称和更新时间。
- 引用的输入版本。
- 参数修改数量与关键参数摘要。
- 状态：草稿、就绪、排队、运行、已完成、失败、已停止、中断、已归档。
- 运行进度或最近完成时间。
- 已完成时显示结果族数与文件数。

主要操作规则：

| 状态 | 可用操作 |
| --- | --- |
| 草稿/就绪 | 打开计算、编辑名称、复制、加入队列、删除 |
| 排队 | 打开计算、从队列取消 |
| 运行 | 打开计算、查看队列、停止 |
| 完成 | 查看结果、导出、复制、归档 |
| 失败/停止/中断 | 查看日志、重试、复制 |
| 归档 | 查看、复制；不可直接编辑 |

新建方案时只要求：名称、输入版本、可选基础方案。基于现有方案创建时复用参数补丁，但产生新的方案标识。

不提供参数差异矩阵或双方案结果对比。

### 5.4 计算工作台

计算工作台是独立完整页面，不是弹窗，也不是从右侧滑入的整页抽屉。

#### 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 返回方案管理  方案名称 / 状态 / 输入版本     保存方案        │
├───────────────────────────────────┬──────────────────────────┤
│                                   │ 输入       摘要           │
│                                   ├──────────────────────────┤
│     始终保持挂载的可视化画布      │ 参数       摘要           │
│           约 60%–68%              ├──────────────────────────┤
│                                   │ 运行       摘要           │
│                                   ├──────────────────────────┤
│                                   │ 结果       摘要           │
└───────────────────────────────────┴──────────────────────────┘
```

- 左侧画布建议占 65%，最小宽度 560px。
- 右侧模块区建议 420–520px，最小宽度 360px。
- 输入、参数、运行、结果是右侧纵向抽屉式折叠模块。
- 同一时间主要展开一个模块，折叠标题始终可见并显示状态摘要。
- 切换模块时左侧画布不得卸载、跳转、清空图层或重置视角。
- 画布视角、显隐图层、选中对象和探针位置属于工作台本地状态。

#### 输入模块

输入模块用于检查项目共享输入，不允许在方案中形成一套私有文件副本。

按文件族分组展示：文件名、类型、大小、校验状态、摘要、警告和错误。点击文件时在左侧画布或数据检查器中显示。

| 输入类型 | 默认呈现方式 |
| --- | --- |
| DEM、坡度、分区、厚度、糙率、地下水、入渗 | 栅格图层、色带、数值探针 |
| 边界、河道、出流边界 | 矢量线/面图层、属性检查 |
| 监测点 | 点图层、编号和属性列表 |
| 降雨、入流、出流、过程线 | 时间序列图表与表格 |
| 配置与原生文本 | 结构化字段、原文预览和校验信息 |

画布工具至少包含：缩放、平移、适应范围、图层显隐、图层顺序、透明度、图例、坐标与数值探针。

输入版本无效时，运行模块必须禁用，并将用户引导到具体错误文件。

#### 参数模块

参数模块从 `/api/parameters/catalog` 生成，不在前端硬编码可编辑权限。

字段内容：中文名称、配置路径、当前有效值、方案覆盖值、单位、运行消费者、启用条件和运行状态。

交互要求：

- 按时间控制、输出控制、物理过程、数值控制和运行模式分组。
- 默认只显示可编辑项；可切换查看只读元数据。
- 修改值时即时校验类型、范围和依赖条件。
- 清除覆盖值后恢复输入版本或基础方案的有效值。
- 显示“已修改 N 项”，支持仅查看修改项。
- 方案不可编辑时，所有字段切换为只读，并提供“复制为新方案”。

#### 运行模块

运行模块不直接创建脱离队列的隐式任务。主操作为“加入模拟队列”。

入队前显示检查清单：输入版本有效、参数通过校验、方案已保存、当前方案不在队列中。

运行中展示：

- 状态与总体进度。
- 当前模拟时间 / 终止时间。
- 步数、输出数和已用时间。
- 终端日志摘要，可展开查看完整日志。
- 停止按钮及二次确认。

WebSocket 用于接收运行快照；连接中断时显示“实时连接已断开，正在轮询”，并继续通过 REST 获取状态。系统不提供暂停与恢复，不应设计相关按钮。

#### 结果模块

未完成时显示明确状态：待模拟、运行中、失败或无结果。已完成时按结果族展示：标签、文件数量、总大小和文件列表。

选择可视化文件后，左侧画布切换为结果图层或图表，但保持视角和输入底图。提供：

- 结果族切换。
- 文件/时刻选择。
- 图例和数值探针。
- 元数据查看。
- 单文件下载与完整结果 ZIP 下载。
- 前往“导出数据”。

当前代码中的画布仍是占位预览；真实栅格解析、图层渲染和结果时序播放属于前端后续实现项，不得用伪造数值代替。

### 5.5 模拟队列

队列按项目管理，默认遵循 FIFO。页面分为“当前运行”和“等待/历史”两部分。

队列项展示：顺序、方案名称、状态、进度、加入时间、开始时间、结束时间、摘要和关联模拟编号。

允许操作：

- 等待项：上移、下移、拖拽排序、取消。
- 运行项：查看计算工作台、停止。
- 失败/停止/中断项：查看日志、重试。
- 完成项：查看结果、导出。

排序完成后立即调用后端并以服务端返回顺序为准。运行中的项目不可被拖动。服务重启造成的活动任务必须显示为“已中断”，由用户主动重试。

### 5.6 导出数据

导出采用四步流程：

1. 选择已完成的参数方案。
2. 选择该方案的一次模拟记录，默认最近完成记录。
3. 选择结果族或具体文件，并包含有效参数文件。
4. 确认内容、生成导出包并下载。

导出内容建议包含：

```text
scenario/
  scenario.json
  effective_parameters.json
results/
  <selected families and files>
manifest.json
```

现有后端接口真实支持按 `simulation_id`、结果族和文件名导出；前端不得把尚未传入后端的 JSON/CSV 选项展示为已生效。若需要额外参数 CSV，应先扩展导出接口。

生成过程展示排队、生成中、已完成和失败状态。失败必须保留错误信息及重新生成入口。

## 6. 状态与反馈

### 6.1 统一状态语言

| 类型 | 中文显示 | 颜色语义 |
| --- | --- | --- |
| draft | 草稿 | 中性灰 |
| ready | 就绪 | 蓝色 |
| queued/waiting | 排队中 | 蓝紫色 |
| starting/running | 启动中/运行中 | 品牌蓝 + 动态指示 |
| completed | 已完成 | 绿色 |
| failed | 失败 | 红色 |
| stopped/cancelled | 已停止/已取消 | 中性深灰 |
| interrupted | 已中断 | 橙色 |
| archived | 已归档 | 灰色 |

颜色只作辅助，必须同时有文字与图标。状态文案在方案、队列和计算工作台中保持一致。

### 6.2 错误反馈

API 错误结构为 `{code, message, details, request_id}`。界面显示可理解的中文说明；详情区域保留错误代码和 `request_id`，用于技术支持定位。

危险操作需要确认：删除方案、停止运行、删除结果。取消等待任务不需要输入确认文字，但需 Toast 撤销提示（仅在后端允许恢复时提供）。

## 7. Fluent 2 视觉规格

### 7.1 总体原则

- 专业、安静、清晰、高信息密度。
- 使用 Segoe UI，数字与路径使用等宽字体。
- 采用 4px 基础间距体系。
- 以中性背景和白色/深色实体表面构成层级。
- 品牌蓝用于主操作、选中和运行状态，不做大面积装饰。
- Mica 仅用于桌面应用背景；Acrylic 仅用于短暂浮层，不用于主内容卡片。
- 避免渐变背景、发光边框、超大圆角、悬浮卡片墙和装饰性仪表盘。

### 7.2 建议 Token

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 20px;
--space-6: 24px;
--space-8: 32px;

--radius-sm: 4px;
--radius-md: 6px;
--radius-lg: 8px;

--control-sm: 28px;
--control-md: 32px;
--control-lg: 40px;

--brand: #0f6cbd;
--brand-hover: #115ea3;
--brand-pressed: #0c3b5e;

```

桌面默认字号：正文 14px，辅助信息 12px，页面标题 28px，区块标题 18–20px。正文行高不低于 1.4。

### 7.3 组件规范

- 按钮：主按钮每个页面最多一个视觉主操作组。
- 卡片：仅用于需要边界的业务实体；列表优先于卡片堆叠。
- 表格：方案管理与队列默认使用表格，窄屏切换为紧凑卡片。
- 抽屉模块：是计算工作台内部的折叠结构，不是覆盖页面的 Drawer 组件。
- Toast：用于操作结果；校验错误必须靠近对应字段显示。
- Tooltip：只解释图标和术语，不承载关键操作说明。

## 8. 响应式与桌面窗口

主目标为 1440×900 与 1920×1080。

- 宽度 ≥ 1280px：计算画布和右侧模块并排。
- 宽度 1024–1279px：右侧固定 400px，左侧自适应；隐藏次要元数据。
- 宽度 < 1024px：允许右侧模块变为可调整宽度的覆盖面板，但画布仍保持挂载；不按移动端重排整个产品。
- 最小支持窗口建议 1024×720。

表格需要粘性表头；长列表使用虚拟滚动或分页。日志区域使用等宽字体并支持自动跟随开关。

## 9. 可访问性

- 所有功能支持键盘访问，焦点顺序符合视觉顺序。
- 折叠模块使用 `aria-expanded` 与关联内容区域。
- 图标按钮必须有可读标签。
- 焦点框不得被移除或仅依赖阴影表达。
- 正文和交互文本达到 WCAG AA 对比度。
- 状态、错误和图层含义不得只依赖颜色。
- 动画尊重 `prefers-reduced-motion`；运行中状态不使用高频闪烁。
- 画布探针结果同时提供可复制文本形式。

## 10. 前端实现建议

### 10.1 目录责任

```text
src/
  api/          API 适配、错误转换、WebSocket/轮询
  stores/       项目上下文、领域数据与视图状态
  layouts/      全局壳与项目导航
  pages/        路由页面
  components/   通用 Fluent 组件
  features/     inputs、scenarios、queue、results、exports
  visualization/ 栅格、矢量、图表与图层状态
  styles/       Fluent tokens、主题和全局样式
```

领域记录以服务端为真源，不写入浏览器持久存储。浏览器仅持久化主题、最近项目和当前项目标识。

### 10.2 API 映射

| 前端任务 | 接口 |
| --- | --- |
| 项目列表/创建/导入 | `GET/POST /api/projects`、`POST /api/projects/import` |
| 输入上传 | `POST /api/projects/{id}/uploads/{family}` |
| 输入版本 | `/api/projects/{id}/input-revisions` |
| 方案管理 | `/api/projects/{id}/scenarios` 及 duplicate/archive |
| 队列管理 | `/api/projects/{id}/queue`、order、stop、retry |
| 运行状态 | `/api/projects/{id}/simulations`、terminal、stop |
| 运行实时快照 | `/ws/simulations/{run_id}` |
| 队列实时快照 | `/ws/projects/{id}/queue` |
| 结果 | `/api/projects/{id}/results/{simulation_id}` |
| 导出 | `/api/projects/{id}/exports` |
| 参数目录 | `GET /api/parameters/catalog` |
| 系统状态 | `GET /api/health`、`GET /api/system/metrics` |

### 10.3 当前实现需要优先修正的问题

1. 多个前端中文字符串存在乱码，必须统一使用 UTF-8 并完成全量文案检查。
2. 可视化画布目前仅绘制网格和占位信息，尚未显示真实输入与结果。
3. 导出页存在前端参数文件选项与后端请求字段不完全一致的问题，需按实际接口校正。
4. 当前前端依赖中没有 Fluent UI React；可继续使用自定义组件，但 Token、交互状态和组件行为必须统一。
5. WebSocket 能力已存在，前端适配器尚未完整使用，应实现实时优先、轮询兜底。

## 11. 验收标准

### 11.1 核心流程

- 用户可以新建或导入项目，并打开项目概览。
- 用户可以上传并校验共享输入，创建确定的输入版本。
- 用户可以创建多个仅参数不同的方案。
- 用户可以从方案进入独立计算工作台。
- 计算工作台切换输入、参数、运行、结果时，左侧画布状态保持不变。
- 用户可以把多套参数方案按顺序加入队列、调整顺序并执行。
- 方案状态、队列状态和运行状态一致。
- 已完成方案能够查看结果族、下载文件并进入导出流程。
- 用户可以选择一次模拟的结果族或文件生成导出包。

### 11.2 质量门槛

- 主要页面在 1440×900 和 1920×1080 下无裁切或横向溢出。
- 所有主操作具有加载、成功、失败和禁用状态。
- 不出现乱码、占位业务文案或伪造计算数据。
- 刷新页面后领域状态能从服务端恢复。
- WebSocket 断开后不丢失任务状态。
- 键盘可以完成项目打开、方案选择、参数编辑、加入队列和导出。
- `npm run build` 通过，核心领域流程有组件或端到端测试。

## 12. 实施优先级

### P0：完整主链路

项目与输入 → 方案管理 → 计算工作台 → 队列 → 结果 → 导出；同时修复中文乱码和前后端字段不一致。

### P1：真实可视化

输入栅格/矢量图层、时间序列、结果图层、探针、图例和图层管理。

### P2：效率与精细体验

大数据渲染优化、列表虚拟化、快捷键、日志检索、窗口布局记忆和更完整的无障碍测试。

## 13. 非目标

- 不实现两方案对比。
- 不实现诊断中心。
- 不允许方案拥有独立输入文件副本。
- 不提供暂停或恢复模拟。
- 不在前端暴露未被生产运行消费的可编辑参数。
- 不修改数值求解器的科学计算语义。
- 不用静态假数据伪装真实输入可视化或模拟结果。
